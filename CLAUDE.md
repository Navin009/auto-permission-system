# auto-permission-system

Pi coding agent extension: two-layer security sandbox + skill docs. Package manifest is the source of truth for what's wired up — see `package.json` → `pi` field:

- `pi.extensions`: `extensions/guard.ts` (L2 in-process tool guard), `extensions/sandbox.ts` (L1 OS sandbox via sandbox-exec/bubblewrap), `extensions/permission-mode.ts` (mode switch), `extensions/tool-view.ts` (display-only tool rows, independent of the security layers)
- `pi.skills`: `skills/auto-permission-system/SKILL.md` (agent-facing how-to, auto-loaded by pi when relevant)

Shared pure logic lives in `src/core/` (the reusable part, no pi/OS imports); the two entrypoints stay thin.

## Commands

```bash
npm run typecheck      # tsc against pi's bundled .d.ts
npm test               # security/tests/*.mjs (path-matcher, url-allowlist, symlink-escape)
./security/check.sh    # tests + regenerate SECURITY.md (or: `tests`|`render` only)
```

## Docs map — read the right one, don't duplicate across them

| File | Audience | Edit? |
|---|---|---|
| `SECURITY.md` | current-state dashboard (layer status, tests, gaps) | **No** — auto-generated by `security/render.mjs` from `security/manifest.json`. Edit the manifest, then run `./security/check.sh` |
| `skills/auto-permission-system/SKILL.md` | pi's own context when helping a user configure/debug the sandbox | Yes, hand-edit |
| `README.md` | human install/config reference | Yes, hand-edit |
| `plan/tool-rows-views.md` | how the `compact` / `full` tool view looks, frame by frame | Yes, hand-edit |
| `plan/scrollable-script-plan.md` | scrollable script/transcript rendering plan | Yes, hand-edit |
| `plan/read-group-plan.md` | combined view for file reads: one `└` line per file in a read run | Yes, hand-edit |
| `llms.txt` | assistants and crawlers: canonical facts, install, commands, terms, doc index | Yes, hand-edit — keep it factually identical to the README |
| `assets/schema.jsonld` | Schema.org JSON-LD (`SoftwareApplication`, `Person`, `FAQPage`) for registries and landing pages | Yes, hand-edit — must stay valid JSON |
| `changes.md` | discoverability strategy: pi.dev/npm/GitHub ranking, then GEO, AEO, E-E-A-T, semantic SEO and schema | Yes, hand-edit |

## Conventions

- Conventional Commits required (`commitlint`); `fix:`/`feat:`/`feat!:` drive semantic-release version bumps on `main`. `docs:`/`chore:`/`refactor:` don't release.
- New non-trivial design decisions → record the reasoning in the commit message body, and in `security/manifest.json` when layer status changes; don't leave it undocumented.
- Policy file shape and layer semantics are documented once, in `skills/auto-permission-system/SKILL.md` — check there before re-explaining sandbox.json fields elsewhere.

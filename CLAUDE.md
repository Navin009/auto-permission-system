# auto-permission-system

Pi coding agent extension: two-layer security sandbox + skill docs. Package manifest is the source of truth for what's wired up — see `package.json` → `pi` field:

- `pi.extensions`: `extensions/guard.ts` (L2 in-process tool guard), `extensions/sandbox.ts` (L1 OS sandbox via sandbox-exec/bubblewrap), `extensions/permission-mode.ts` (mode switch), `extensions/tool-view.ts` (display-only tool rows, independent of the security layers)
- `pi.skills`: `skills/auto-permission-system/SKILL.md` (agent-facing how-to, auto-loaded by pi when relevant)

Shared pure logic lives in `src/core/` (the reusable part, no pi/OS imports); the two entrypoints stay thin.

## Commands

```bash
npm run typecheck      # tsc against pi's bundled .d.ts
npm test               # security/tests/*.mjs (path-matcher, url-allowlist, symlink-escape)
./security/check.sh    # tests + regenerate SECURITY.md (or: `tests`|`render` only)
```

The harness lives under `security/tests/`: `unit/` for pure core logic, `contract/` for adapter logic driven by a scripted UI, `e2e/` for the real OS sandbox (`APS_E2E=1`, opt-in). A new test is a script that prints `PASS=<n>, FAIL=0` and exits non-zero on failure; register it in the matching `manifest.layers[].tests` entry as `node --import ./security/tests/ts-loader.mjs security/tests/unit/<file>.mjs` and `check.sh` picks it up. A new layer is one object in `manifest.layers[]` with `id`, `name`, `status`, `purpose`, `sourceFiles`, `tests`, `knownGaps`.

## Releases

A pushed tag releases; nothing else does. `git tag` + `git push` creates the GitHub Release and commits nothing.

```bash
git tag -a v6.2.0 -m "fix(guard): handle X"
git push origin v6.2.0          # or: git push --tags
```

- `.github/workflows/release-tag.yml` runs on `push: tags: v*`: typecheck + tests, then `gh release create <tag> --generate-notes`. No release commit, no `CHANGELOG.md` edit, no `package.json` bump — the tag is the version of record.
- The notes are GitHub's auto-generated notes for `previous tag → tag`, so the grouping is GitHub's default rather than semantic-release's Conventional Commit sections.
- Bump `package.json` → `version` and `CHANGELOG.md` yourself before tagging when you want the files in step with the tag; the workflow only warns on a mismatch, it never edits them.
- A tag whose typecheck or tests fail produces no Release page. `ci.yml` runs on pull requests only, so this tag run is the release gate.
- `release.yml` (semantic-release: version bump commit + `CHANGELOG.md` commit + tag + npm publish) is `workflow_dispatch` only now — start it by hand (`gh workflow run release.yml`) when you want that fully automated path instead.
- Re-tagging is only safe before the Release page exists: once it is created, the workflow skips instead of overwriting it.
- `NPM_PUBLISH` (repository variable, default off) gates npm publishing and is read only by the manual `release.yml` path.
- Verify after: `git pull --tags`, `gh release list --limit 3`, `gh release view <tag>`.

npm is a second, independent path. The package is already published; later versions go out through `release.yml` with `NPM_PUBLISH=true`, and npm Trusted Publishing (OIDC, so provenance is attached and no token is stored) is configured for this repo. The [Pi package gallery](https://pi.dev/packages) lists whatever npm has — there is no separate upload, so a publish is all the discoverability that needs doing. Verify with `npm view auto-permission-system version`.

## Conventions

- Conventional Commits required (`commitlint`); `fix:`/`feat:`/`feat!:` drive the version bump, and the release itself is triggered by the word `release` in the commit message — see `## Releases`. `docs:`/`chore:`/`refactor:` don't release.
- New non-trivial design decisions → record the reasoning in the commit message body, and in `security/manifest.json` when layer status changes; don't leave it undocumented.
- Policy file shape and layer semantics are documented once, in `skills/auto-permission-system/SKILL.md` — check there before re-explaining sandbox.json fields elsewhere.
